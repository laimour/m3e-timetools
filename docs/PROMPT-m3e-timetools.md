颜色分配规则（必须同时满足「同名同色、跨天稳定」与「不同名不同色」）：

- 维护 `name → colorIndex` 的颜色注册表，持久化在数据库。
- 首次出现某名称：`hash(name.trim().toLowerCase())` 取模 16 作为初始索引；若该索引已被其他名称占用，则向后**线性探测**到空位并登记。
- 之后同名永远读注册表，保证跨天、跨刷新稳定；不同名称不会共用同一色。
- 名称比较使用 trim + 小写归一，但展示保留用户原始写法。

## 3. 功能需求（P0，必须全部完成）

### 3.1 先命名，再计时

- 点击「开始计时」先展开命名表单，**名称必填**；空白/纯空格提交时拒绝并提示。
- 历史名称以胶囊/下拉列表展示，按使用频次排序（常用置顶），每项带该名称的颜色圆点；点选即填入。
- 命名后选择模式，**只有这两种**：
  - 正计时；
  - 倒计时（按设定时长）：预设 15 / 25 / 45 / 60 分钟 + 自定义（1 分钟–24 小时，输入校验）。结束点 = 首段开始时间 + 设定时长，**不提供「倒计时到某个钟点」的模式**。
- 开始后立即创建运行中的记录，并在时间盘上实时伸长。

### 3.2 24 小时环形时间盘（核心视图）

- SVG 圆盘，固定展示今天 00:00–24:00，0:00 在正上方（-90°），顺时针到 24:00 回到顶部；24 小时均分角度。
- 每条记录按本地时区的起止时刻画成圆环弧段，填充该事件颜色；弧段之间留 **2°–3° 视觉间隙**（不改变真实角度映射，绘制时内缩）。
- 跨零点的记录必须按天切分，在两天各自的时间盘显示对应片段；角度按「当天 0:00–24:00」裁剪，跨天片段不得串天。
- 当前时间：一条细淡紫指针（圆心到环）+ 环上光点；每秒更新；运行中记录的弧段末端跟随当前时间实时伸长，并带极轻的呼吸发光。
- 悬停弧段：浮层显示名称、起止、时长（运行中显示「进行中」）；点击：打开详情面板。
  详情包含：名称、模式、起止时间（跨天标注日期）、净时长与首尾跨度、备注、暂停区间列表、修改记录（see 3.6）；支持编辑名称/时间/备注、删除（删除需二次确认）。
- 盘中心信息区：今日累计、当前运行事件与已计时长（或倒计时剩余）、当天已完成记录段数。
- 环外侧（或内侧）叠加 `WaveRing`：
  - 默认显示「当天进度 = 已过时间 / 24h」；
  - 若当前正在倒计时，内圈再叠加一条 `WaveRing` 表示「剩余 / 总时长」，不足 10% 时用 `--m3e-warn` 色调。
- 无障碍：每个弧段可聚焦，带 `aria-label`（名称 + 起止 + 时长）；指针与运行段不能只靠颜色区分。
- SSR 安全：盘面必须客户端挂载后计算（`<ClientOnly>` 或 `onMounted` 时钟状态），不允许 hydration mismatch。

### 3.3 计时引擎（正确性优先）

**核心原则：不要用定时器累加时长。** 真实数据是「`Date.now()` 开始时间戳 + 分段区间」，展示时现算差值。定时器只负责重绘。

数据结构（示意，最终类型需放 `shared/types.ts`）：

```ts
interface Segment { start: number; end: number | null }   // epoch ms；null = 正在运行
interface TimeRecord {
  id: string;
  name: string;
  colorIndex: number;
  mode: 'countup' | 'countdown';
  targetMs: number | null;        // 倒计时总时长
  note: string;
  interrupted: boolean;           // 用户可标记「有中断」
  segments: Segment[];            // 暂停 = 关闭当前段，继续 = 新开一段
  createdAt: number;
  updatedAt: number;
  revisions: Revision[];
}
interface Revision { at: number; field: string; before: unknown; after: unknown }
```

- `netMs(record, now)` = 所有分段时长之和（开放段用 `now - start`），**不含暂停间隙**。
- `spanMs(record, now)` = 首段开始 → 末段结束（或 now），**含暂停间隙**。
- 暂停：关闭当前分段并记录 `pausedAt`；继续：新开一段。暂停状态下界面明确显示「已暂停」与暂停累计时长。
- 快速切换：在计时面板直接点另一个历史事件 → 结束当前记录（以当时时间戳为终点）并开始新记录，不弹二次确认。
- 所有 UI 秒级刷新统一走一个 `useClock`（一个 `setInterval`/`requestAnimationFrame`，页面隐藏时暂停刷新，恢复可见时立即重算），不要每个组件各自开定时器。
- **未结束计时恢复**：启动/刷新后读取到存在开放分段（或暂停中）的记录时，**必须弹窗让用户选择**，不能静默处理：
  - 「算到现在」（正计时默认） / 「算到推定结束点」（倒计时默认，= 首段开始 + targetMs） / 「结束于指定时间」（手动输入） / 「继续计时」（若会话未中断，可从原段继续）。
  - 倒计时在关闭期间已超过推定结束点：默认预选「算到推定结束点」，并显示超出分钟数。
  - 取消弹窗不得静默结束记录，最多保持未结束状态并再次提示。
- 倒计时结束：
  - 以 **首段开始 + targetMs** 为结束点自动结束并生成/落库该记录（不是以发现结束的 tick 时间为终点）。
  - 声音提醒：Web Audio API 合成提示音（无外部音频文件），需在用户首次点击开始时解锁 AudioContext；页面内同时出现明显提示条/卡片 + 顶部 toast + 窗口标题闪烁（页面重新可见时停止）。
  - 若应用在后台且浏览器禁止发声，回到页面时必须仍能看到提示条与 toast，不能静默。
- 手动补记：输入日期 + 开始/结束时间（可跨零点，校验结束必须晚于开始），可选备注；归属日期按开始时间所在本地日期。
- 时区：全部使用浏览器本地时区（`Intl.DateTimeFormat` / 本地 `Date` 取值），不写死 UTC+8。

### 3.4 自研波浪进度组件（必须真用）

实现两个可复用组件，并**在界面中实际使用**：

- `WaveBar`（直线）：列表记录条、今日目标预算条、统计卡的「达成度」。
- `WaveRing`（环形）：时间盘外侧当天进度、内圈倒计时剩余、专注/运行中进度。

技术要求：

- 正弦波相位动画（相位随时间推进），不要用静态波纹贴图，也不要引第三方动画库。
- 波形描边 + 半透明渐变填充；暗色下用 `feGaussianBlur` 形成柔和发光（低不透明度，不要霓虹感）。
- `WaveBar`：圆角轨道 + 波浪填充，波幅 ≤ 厚度/3，波峰数量随宽度自适应；`value` 0–1；接近 0 时不显示波浪，接近 1 时停止溢出轨道。
- `WaveRing`：沿圆弧生成极坐标正弦路径；支持 `value` 0–1、起始角、缺口（用于盘面留白）；描边渐变 + 发光；`tone` 支持 `accent` / `muted` / `warn`。
- 公共 props：`value: number`、`thickness`、`tone`、`speed`（默认低频慢速）、`aria-label`；`prefers-reduced-motion` 时静止。
- 所有波浪共享同一个动画时钟，页面隐藏时暂停，避免多个 rAF 空转。
- 规则写死在界面里：全局进度/剩余用环形，单项预算/列表条目用直线。

### 3.5 统计面板（对齐参考图）

- 顶部三张卡：**今日 / 本周 / 本月**，每张包含：
  - 标题（内联 SVG 小图标 + 名称）；
  - 右上角「峰值 X」；
  - 大号累计时长（例如「3 小时 20 分」，单位缩小）；
  - 辅助行：累计天数 / 连续天数 / 峰值日期；
  - 与参考图相同的深灰圆角卡片质感。
- 热力图：
  - 今日热力图：24 格（按小时），颜色 0–5 档，标注时段刻度（0、6、12、18、24）。
  - 本月热力图：按天网格（GitHub 贡献图式：周一为行首，7 列），顶部月份或日期标注，底部「一 二 三 四 五 六 日」，右下「少 [5 格] 多」图例，样式贴近参考图。
  - 档位量化用纯函数（例如按分位数或固定阈值），空白天为 `--m3e-heat-0`。
- 两个额外口径（数字与说明都要展示，必须带问号 tooltip 解释公式，避免歧义）：
  - **有效时长 vs 总时长**：
    - 总时长 = 每条记录「首段开始 → 末段结束」的跨度之和（含暂停间隙），按天裁剪后计入当天。
    - 有效时长 = 所有分段净时长之和（排除暂停间隙）；带「中断」标记的记录，其净时长仍计入有效（标记只做分类，不剔除）。
  - **碎片率**：
    - 单段净时长 < 5 分钟视为碎片；
    - 同时展示「碎片段数占比」和「碎片时长占比」，并在 tooltip 中写明口径。
- 周起始为周一，`zh-CN` 格式；连续天数按本地日期计算，允许今天未记录时从昨天起算。
- 所有统计由纯函数从记录集合计算，不在模板里散写逻辑。

### 3.6 数据、持久化与修改痕迹

- 单一数据源：服务端 JSON 文件（默认 `./.data/store.json`，可用环境变量 `M3E_DATA_DIR` 覆盖），目录自动创建，写入必须**原子化**（写临时文件 → rename），并用串行写队列避免并发覆盖。
- 首次运行自动生成空库结构；文件损坏时先备份为 `store.corrupt-<timestamp>.json`，再以空库启动并在 UI 提示，不得直接抛白屏。
- 保存 schema 版本号，读取时做最小迁移/校验。
- 修改痕迹：任何**时间、名称、模式、备注**的编辑都要追加 `revisions`（字段、改前、改后、修改时间）；详情面板展示「修改记录」列表；删除记录也要留一条删除痕迹（可在导出中出现）。绝不静默覆盖。
- 导出：
  - `GET /api/export?format=json` → 全量数据（含 revisions、颜色注册表、schema 版本）；
  - `GET /api/export?format=csv` → 每条记录一行：日期、名称、模式、开始、结束、净时长、跨度、暂停次数、中断标记、备注；CSV 用 UTF-8 **BOM**，时间用本地 ISO 风格 `YYYY-MM-DD HH:mm:ss`；
  - 前端 header 提供「导出 JSON / 导出 CSV」。
- 数据本地优先、无账号、无云同步；刷新/重启后数据仍在。

### 4.2 API 契约（需服务端校验）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/data` | 返回 `{ schemaVersion, records, colorRegistry, active }` |
| POST | `/api/records` | 新建记录（含运行中记录） |
| PATCH | `/api/records/[id]` | 更新记录；涉及时间/名称变更时由**服务端**追加 revisions |
| DELETE | `/api/records/[id]` | 删除并留删除痕迹 |
| GET | `/api/export?format=json|csv` | 导出 |

- 若服务端无法可靠判定「改前/改后」，则以客户端提交的 `before` 快照为输入，但服务端仍要按当前库内值校验并落库，防止前端算错。
- 客户端所有写操作经 `useRecords`，失败时 toast 明示「保存失败，数据仍在本地待重试」，不要假装成功。

## 5. SSR / 运行时安全

- 所有依赖 `Date.now()` 的渲染、`window`、`localStorage`、`AudioContext` 只能在 `onMounted` 之后使用。
- 时间盘、统计热力图、波浪组件用 `<ClientOnly>` 或客户端挂载后渲染，避免 hydration mismatch 与控制台警告。
- 服务端渲染时提供一个稳定的空态骨架，避免首屏闪烁过重。
- 页面隐藏（`visibilitychange`）暂停动画与高频刷新；恢复时立即重算，不依赖累计。
- 所有定时器在 `onUnmounted` 清理。

## 6. 纯函数自检与测试

使用 Vitest，`npm run test` 必须通过；另加 `npm run typecheck`（`nuxt typecheck` 或 `vue-tsc`）。

至少覆盖：

1. `splitByDay(record)`：23:40–00:20 切成两段，两天总和不重复不遗漏；单段正好跨零点；全年最后一天。
2. `netMs` / `spanMs`：暂停区间只进 span 不进 net；开放段用传入 now；空分段返回 0。
3. `countdownEnd(start, targetMs)`：结果只由时间戳决定，与 tick 无关；休眠恢复后仍准确。
4. `nameToColor`：同名归一化稳定；200 个常见名称经注册表无重复；刷新/重启后映射不变。
5. `arcPath`：起点 0:00 在顶部；满 24 小时闭合无缺口异常；跨天片段角度正确。
6. `fragmentation`：<5 分钟段数与时长占比；恰好 5 分钟不算碎片。
7. `heatLevel`：0 时长 → 0 档；最大值 → 5 档；中间单调。
8. `weekRange` / `streak` / `peak`：周一为起点；连续天数跨月正确。
9. `formatDuration`：0、59 秒、1 小时、24 小时的显示规则（中文）。

测试断言即自检；不需要 UI 测试框架，但浏览器验收必须人工/自动化走一遍。
